## 先验证录后主路径

1. 以自己的 Bundle ID 和 Team 在配对设备安装两端 App。在 iPhone 确认识别方式并授权。
2. 在 Watch 选择“录后转写”，说出一段带编号的中文，例如“第一条，今天测试离线录音”。
3. 结束后检查手表显示保存状态。恢复／保持连接，等待 iPhone 列表出现记录和 Watch 接收确认。
4. 播放原音频，核对起止内容和时长。等待转写，核对全文与原音频，手动编辑、保存并重启 App。
5. 导出 TXT 和原音频到系统“文件”App，重新打开验证内容。删除手机记录，确认不会因重复同步复活。
6. Watch 副本应仍存在。只在手机确认收到之后允许手动删除手表副本。

## 离线／重启／中断

| 场景 | 操作 | 期望行为与证据 |
| --- | --- | --- |
| 手机不可达 | 确认两端状态显示不可达，Watch 录音并停止，再恢复连接 | 本地文件始终存在；连接恢复后同步且只出现一个 ID |
| 转写时断网 | 用户已允许在线识别；在转写中使网络不可用 | 明确失败或已由本地识别完成，不显示虚假完成；原音频保留，重试可使用已保存段 |
| Watch 录音中断 | 录音时制造系统音频中断／切换 App／熄屏，分别测试 | 保存可用音频或继续录音的行为与 UI 一致；记录系统原因、最后可播放位置 |
| 录音进程终止 | 在独立测试数据上终止 Watch App，再启动 | 尝试恢复 CAF 可读帧；不能恢复时保留原文件并显示错误；不宣称整段恢复 |
| 手机转写进程终止 | 已完成至少两段时终止 iPhone App，再启动并重试 | 显示中断；已持久化分段不丢失；最终顺序正确 |
| 传输／确认延迟 | 手机接收后、手表收到确认前恢复／切换连接，手动重试同步 | 手机 UUID 去重；仅在确认后允许清理 Watch 副本 |
| 手机删除后的延迟重传 | 手机删除记录后重新触发同一 ID 的传输 | tombstone 阻止记录复活，手表可获得接收处理确认 |
| 磁盘不足 | 使用测试设备和可恢复数据制造写盘失败 | 停止／报错且不伪报保存成功；释放空间后重试，先前已保存段仍在 |

不要把仅关闭 Wi-Fi 当作 WatchConnectivity 已断开；以两端实际可达状态和回调为准。

## 实时链路

1. iPhone App 前台且已授权，两端可达。Watch 选择实时，连续说出带时间／编号的句子，检查双端字幕。
2. 使两端不可达，继续说话；本地计时与保存不应因字幕失效而停止。
3. 恢复连接，检查自动重连及新 stream 的字幕，确认旧流字幕和错误不会覆盖新流。
4. 在长期失败条件下检查重试间隔逐渐增加，六次后暂停自动尝试，可通过手动重连重新开始。
5. 停止录音，检查不再继续重连。完整音频同步后，最终全文应来自录后转写，而非仅最近的实时字幕。
6. 分别测试手机锁屏、后台、Watch 熄屏、低电量。记录不受支持的行为，不将持续实时可用作为验收假设。

## 长音频

分别测试 5、30、60 分钟。按固定间隔说出编号，包含在 40 秒分段边界前后的词句和短暂无声。
比对音频时长、各编号是否存在、分段顺序、边界丢字／重复、静音段处理、总耗时与错误重试位置。
记录双端容量、电量和温度变化；48 kHz 单声道 PCM 约 346 MB/小时，不能假设手表容量无限。

只有以上实际设备证据齐备后，才能宣称对应功能通过真机验收或把 PR 从待验收状态推进到发布评审。
